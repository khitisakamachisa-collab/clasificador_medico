### 🗺️ Flujo de Trabajo de Implementación (Paso a Paso)

#### **FASE 1: Externalización y Corrección de Reglas (Prioridad Absoluta)**
*Objetivo: Dejar de "adivinar" con NLP cuando hay una regla clara y corregir los errores evidentes del historial.*
1. **Crear el archivo de reglas maestras**: Crear `data/rules/reglas_maestras.xlsx` (o `.json`) con columnas: `palabra_clave`, `categoria`, `emdn_code`, `mdr_class`, `criticidad`.
2. **Poblar con correcciones**: Incluir explícitamente las fallas del historial:
   - `"lámpara exploración"` → `CIR-01`, `Z120107` (o `Z129004` según corresponda).
   - `"monitor secuencial"` → `MON-01`, `Z12030202`.
   - `"bisturí armónico"` / `"harmonic"` → `CIR-02`, `Z12010902` (o `K0202010201` si es desechable).
   - `"cama uci"` / `"resucitación"` → `MOB-01`, `V08060102`.
3. **Actualizar el Backend**: Modificar el motor de reglas (`rules_engine.py` o similar) para que lea este archivo en lugar de tener las reglas "hardcodeadas" en el código Python.

#### **FASE 2: Corrección del Flujo de Corrección Manual (El bug del 0%)**
*Objetivo: Que cuando el humano corrige, el sistema lo acepte como "Verdad Terrestre" (Ground Truth) para el registro del CMMS.*
1. **Modificar el endpoint `/api/v1/recalcular`**: Cuando el usuario selecciona manualmente una categoría del menú, el backend debe devolver:
   - `confianza`: `0.95` (o `1.0`), porque la validación humana es la fuente de verdad para el inventario.
   - `semaforo`: `verde`.
   - `metodo`: `CORRECCION_MANUAL`.
   - *Nota*: El sistema debe guardar en un log separado que el NLP original falló, para saber qué aprender, pero el registro final del equipo debe quedar en verde para el CMMS.

#### **FASE 3: Mejoras de Interfaz de Usuario (UI/UX)**
*Objetivo: Prevenir errores de escritura y hacer la interfaz más profesional.*
1. **Menú desplegable para "Ubicación"**: Reemplazar el campo de texto libre por un `<select>` con opciones predefinidas (UCI, Quirófano General, Urgencias, Fisioterapia, Mobiliario, etc.) y una opción "Otro" con campo de texto.
2. **Ajuste visual del Semáforo y Confianza**: 
   - Asegurar que el semáforo lea correctamente el valor de `confianza` que viene del backend (para que no se quede en rojo si el backend ya envió 95%).
   - Aumentar el tamaño de la fuente del porcentaje de confianza (ej. `font-size: 2em; font-weight: bold;`).

#### **FASE 4: Preparación para Integración CMMS y Aprendizaje (Futuro Cercano)**
*Objetivo: Dejar el sistema listo para tu tesis de mantenimiento predictivo.*
1. **Endpoint de Webhook/API para el CMMS**: Asegurar que cuando un equipo se clasifica (sea por regla o por corrección manual), el CMMS pueda recibir ese dato vía API.
2. **Log de Aprendizaje**: Guardar en una tabla `training_corrections` los casos donde el NLP falló pero el humano corrigió. Esto será tu "dataset de oro" para, en una siguiente fase, hacer *fine-tuning* (ajuste fino) de un modelo BERT médico o mejorar las reglas automáticamente.
